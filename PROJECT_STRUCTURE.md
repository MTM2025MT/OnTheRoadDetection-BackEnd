# PotholeApi — Project Structure & Build Guide

A blueprint of how this project is built, so you can reproduce the same architecture for a similar system
(e.g. a "report incidents on a map → assign work → track repair" backend).

---

## 1. What the project is

An **ASP.NET Core 8 Web API** for pothole reporting and road maintenance.

| Concern | Technology |
|---|---|
| REST API | ASP.NET Core controllers (`[ApiController]`) |
| High-throughput ingestion | gRPC client-streaming + in-memory queue + background worker |
| Database | SQL Server via EF Core 8 (code-first migrations) |
| Spatial data | `geography` columns via NetTopologySuite (points, polygons) |
| Auth | ASP.NET Identity + JWT access token + refresh token in HttpOnly cookie |
| Authorization | Role-based (`Admin`, `Officer`, `Manager`, …) |
| Image storage | Cloudinary |
| Logging | Serilog (console + Seq) |
| Docs | Swagger / Swashbuckle |
| Frontend | React (CORS allowed for `http://localhost:5173`) |
| Tests | xUnit, EF InMemory, Moq, AutoFixture, FluentAssertions |

**Domain:** an external AI detector (or a user) reports **Potholes** at a GPS point. Each pothole is automatically
placed into a **Neighbourhood** (inside a **District**) using a spatial point-in-polygon query. **Officers** create
**JobTasks** that assign a pothole to a **RepairTeam**. Officers can also schedule **ScanExecutionTasks** (vehicle
routes that scan for potholes). Dashboards aggregate the data.

### Layering

```
HTTP request ─► Controller ─► Repository ─► Context (EF Core) ─► SQL Server
                    │
                    └─► Service (photo upload, dashboards, role handlers)

gRPC stream ─► DetectionImplementationService ─► DetectionQueue (Channel)
                                                      │
                          DetectionDatabaseWorker (BackgroundService) ─► Cloudinary + DB (batches of 100)
```

> **Mid-refactor note:** most controllers talk directly to repositories (some even to `Context`). The `*Service` /
> `I*Service` stubs (`AccountService`, `OfficerService`, …) are empty placeholders not registered in DI. In a new
> project, pick one approach up front: **Controller → Service → Repository** is the cleaner target.

## 3. Domain model (`Models/`)

| Entity | Key fields / relations |
|---|---|
| `Pothole` | `Point? Location` (geography, SRID 4326), `Level LevelOfSeverity`, `RepairStatus Status` (default Pending), `ImageUrl`, `ReportedAt`, `confidence`, FK `NeighbourhoodId`. `Latitude`/`Longitude` are `[NotMapped]` getters over `Location`. |
| `District` | `Geometry` (geography polygon), has many `Neighbourhood` |
| `Neighbourhood` | `Geometry` (geography), FK `DistrictId` |
| `Officer` | 1:1 optional with `ApplicationUser` (`ApplicationUserId`), `BadgeNumber`, `Rank`, `Department`, FK `DistrictId`, has many `JobTask` |
| `RepairTeam` | has many `JobTask` |
| `JobTask` | FKs `PotholeId` (1:1), `OfficerId`, `RepairTeamId`; `AssignedAt`, `Priority`, `Notes`, `Materials`, `Budget` (decimal 18,2). All `DeleteBehavior.Restrict`. |
| `ScanExecutionTask` | `VehicleId`, `StartTime`, `Type` (OneTime/Recurring), `IntervalHours`, `Priority`, `RoutePoints`, `RoutePath` |
| `ApplicationUser : IdentityUser` | adds `FirstName`, `LastName`, `RefreshToken`, `RefreshTokenExpiryTime` |
| Enums (`Models/Enums.cs`) | `Level` {Low=1, Medium, High, Critical}, `Priority` {Low=1, Medium, Urgent, Emergency}, `RepairStatus` {Pending=1, InProgress, Fixed} |

### Context configuration (`Context.cs`)
- Inherits `IdentityDbContext<ApplicationUser>` → Identity tables come for free.
- One `DbSet<T>` per entity.
- `OnModelCreating` (Fluent API) sets: geography column types, default values (`Status = Pending`,
  `Priority = Low`), the Officer↔User 1:1, and JobTask's three relationships with `Restrict` delete.

## 4. How an endpoint is built (the repeatable recipe)

Every feature follows the same 5 steps. Example: **"get potholes by neighbourhood"**.

**1. Entity** → `Models/Pothole.cs` (+ `DbSet` in `Context.cs`, then a migration).

**2. Repository interface** → `IRepositories/IPotholeRepository.cs`
```csharp
Task<ICollection<Pothole>> GetPotholesByNeighbourhoodIdAsync(int neighbourhoodId);
```

**3. Repository implementation** → `Repositories/PotholeRepository.cs`
```csharp
public class PotholeRepository : IPotholeRepository
{
    private readonly Context _context;
    private readonly ILogger<PotholeRepository> _logger;
    public PotholeRepository(Context context, ILogger<PotholeRepository> logger) { ... }

    public async Task<ICollection<Pothole>> GetPotholesByNeighbourhoodIdAsync(int neighbourhoodId)
        => await _context.Potholes.Where(p => p.NeighbourhoodId == neighbourhoodId).ToListAsync();
}
```

**4. Register in DI** → `Program.cs`
```csharp
builder.Services.AddScoped<IPotholeRepository, PotholeRepository>();
```

**5. Controller action** → `Controllers/PotholeController.cs`
```csharp
[Route("api/[controller]")]
[ApiController]
[Authorize(Roles = "Admin,Officer")]
public class PotholeController : ControllerBase
{
    // repositories + ILogger<T> injected through the constructor

    [HttpGet("GetByNeighbourhoodId/{neighbourhoodId}")]
    public async Task<IActionResult> GetPotholesByNeighbourhoodId(int neighbourhoodId)
    {
        try
        {
            var result = await _potholeRepository.GetPotholesByNeighbourhoodIdAsync(neighbourhoodId);
            return Ok(result);
        }
        catch (Exception ex)
        {
            _logger.LogError(ex, "error for neighbourhood {Id}", neighbourhoodId);
            return StatusCode(500, "Internal server error: " + ex.Message);
        }
    }
}
```

**Conventions used throughout**
- Route: `api/[controller]` → `/api/Pothole`, `/api/Officer`, …
- Custom action names via `[HttpGet("GetAll")]`, `[HttpGet("{id}/jobtasks")]`, `[HttpPatch("{id}/Status")]`.
- Return `Ok(...)`, `NotFound()`, `BadRequest(ModelState)`, `StatusCode(500, ...)` through `IActionResult`.
- Write endpoints take a **DTO** (`[FromBody]` JSON or `[FromForm]` for file upload), validated with
  DataAnnotations (`[Required]`) and checked via `ModelState.IsValid`.
- Structured logging with message templates (`"pothole {PotholeId}"`), not string interpolation.
- Reads that don't modify use `.AsNoTracking()`; related data via `.Include(...)`.

## 6. Authentication & authorization

1. **Register/Login** (`AccountController`) use `UserManager<ApplicationUser>`.
2. On login a **JWT** is built with claims (`Email`/`Name`, `NameIdentifier`, one `Role` claim per role),
   signed with HMAC-SHA256 using `JWT:Secret`, issuer `PotholeServer`, audience `PotholeReactApp`,
   **15-minute** lifetime.
3. A **refresh token** (random string from `Helpers/GenerateRefreshToken`) is stored on the user
   (`RefreshToken`, `RefreshTokenExpiryTime` = +7 days) and sent as an **HttpOnly, Secure, SameSite=None cookie** named `jwt`.
4. `GET /api/Account/Refresh-Token` reads the cookie and issues a new access token.
5. `Program.cs` configures `AddIdentity<ApplicationUser, IdentityRole>().AddEntityFrameworkStores<Context>()`
   and `AddJwtBearer` with issuer/audience/signature/lifetime validation and `ClockSkew = Zero`.
6. Controllers protect endpoints with `[Authorize(Roles = "...")]`.
7. Middleware order matters: `UseCors` → `UseAuthentication` → `UseAuthorization` → `MapControllers`.

### Role assignment — strategy pattern
`AdminController.AssignRole` accepts a **polymorphic DTO** (`BaseRoleAssignmentDto`) using
`[JsonPolymorphic(TypeDiscriminatorPropertyName = "roleType")]` + `[JsonDerivedType(...)]`:

```json
{ "roleType": "Officer", "userId": "…", "badgeNumber": "B123", "rank": "Sgt" }
```

All `IRoleHandler` implementations (`OfficerHandler`, `AdminHandler`, `ManagerHandler`) are registered in DI; the
controller picks the one whose `RoleName` matches the DTO's `RoleName`, which adds the Identity role **and** creates
the role-specific record (e.g. an `Officer` row). To add a role: new `XxxAssignmentDto` + `[JsonDerivedType]` +
new `XxxHandler : IRoleHandler` + `AddScoped<IRoleHandler, XxxHandler>()`.
(`RepairTeamHandler` is not implemented yet.)

## 7. Spatial data

- Packages: `Microsoft.EntityFrameworkCore.SqlServer.NetTopologySuite`, `NetTopologySuite.IO.GeoJSON4STJ`.
- Enable: `options.UseSqlServer(cs, o => o.UseNetTopologySuite())` and add `GeoJsonConverterFactory` to the
  controllers' JSON options so geometries serialize as GeoJSON.
- Columns: `.HasColumnType("geography")`, **SRID 4326** (GPS).
- **Coordinate order: `new Point(longitude, latitude)`** — X = longitude, Y = latitude.
- Auto-assign neighbourhood on create:
  ```csharp
  _context.Neighbourhoods
      .Where(n => n.Geometry != null && n.Geometry.Intersects(pothole.Location))
      .Select(n => (int?)n.Id).FirstOrDefaultAsync();
  ```
- Bounding-box query: build a closed counter-clockwise `Polygon` (`GetPotholesByRange`) and filter with `.Intersects(bbox)`.
- District/neighbourhood polygons are loaded from `Data/export.geojson` by `Helpers/DistrictSeeder` (copied to output).

## 8. Detection ingestion pipeline (gRPC → queue → worker)

Use this pattern for any high-volume write path: **never hit the DB on the request thread.**

1. **Contract** — `Protos/DetectionService.proto`:
   `rpc AddData (stream PotholeRequest) returns (StreamSummary);` (location, severity, description, timestamp,
   image bytes, bounding boxes, confidence). Registered in the csproj as
   `<Protobuf Include="Protos\DetectionService.proto" GrpcServices="Server" />`.
2. **Server** — `GrpcServices/DetectionImplementationService : DetectionService.DetectionServiceBase` reads the
   stream, maps each message to a `DetectionQueueItem`, writes it to the queue, returns a `StreamSummary`.
3. **Queue** — `Models/DetectionQueue`: singleton wrapping `Channel.CreateBounded<DetectionQueueItem>(10000)`
   (`QueuePotholeAsync`, `ReadAllAsync`).
4. **Worker** — `Services/DetectionDatabaseWorker : BackgroundService` drains the queue; per item it creates a DI
   scope, uploads the image via `IPhotoService`, maps numeric severity to `Level` (`>=7` High, `>=4` Medium, else Low),
   and `AddRange` + `SaveChanges` in **batches of 100** (flushing the remainder on shutdown).
5. **Wiring** (`Program.cs`):
   ```csharp
   builder.Services.AddGrpc();
   builder.Services.AddSingleton<DetectionQueue>();
   builder.Services.AddHostedService<DetectionDatabaseWorker>();
   app.MapGrpcService<DetectionImplementationService>();
   ```

> Background services are singletons, so they must create a scope (`IServiceProvider.CreateScope()`) to use scoped
> services such as `Context` or repositories.

Also see `DashboardCacheRefreshWorker`: a `BackgroundService` using `PeriodicTimer` (5 min) to recompute each
officer's dashboard and store it in `IMemoryCache`; `PotholeDashboardsService` serves from cache and falls back to
computing on a miss.

## 9. Configuration (`appsettings.json`)

Sections: `ConnectionStrings:DefaultConnection`, `JWT:Secret`, `CloudinarySettings` (bound to
`Helpers/CloudinarySettings` with `Configure<T>` / `IOptions<T>`), and `Serilog` (console + Seq sinks, read via
`UseSerilog((ctx, svc, cfg) => cfg.ReadFrom.Configuration(...))`).

> **Warning:** this repo has real secrets committed in `appsettings.json`. For a new project, put them in
> **user secrets** (`dotnet user-secrets`), environment variables, or a secret store, and rotate the existing ones.

## 10. Program.cs checklist (what to register, in order)

1. Serilog bootstrap logger + `UseSerilog`
2. `AddControllers().AddJsonOptions(GeoJsonConverterFactory, ReferenceHandler.IgnoreCycles)`
3. `AddEndpointsApiExplorer` + `AddSwaggerGen`
4. `AddGrpc`, queue singleton, hosted workers
5. Repositories (`AddScoped<IX, X>`), services, `IRoleHandler`s, `AddMemoryCache`
6. `Configure<CloudinarySettings>`
7. `AddDbContext<Context>(UseSqlServer + UseNetTopologySuite)`
8. `AddIdentity` → `AddEntityFrameworkStores<Context>` → `AddDefaultTokenProviders`
9. `AddAuthentication().AddJwtBearer(...)`
10. `AddCors` (named policy, specific origin, `AllowCredentials` for the cookie)
11. `Build()` → `MapGrpcService` → `UseSerilogRequestLogging` → Swagger → `UseHttpsRedirection` → `UseCors` →
    `UseAuthentication` → `UseAuthorization` → `MapControllers` → `Run`

Seeding (`IdentitySeed.SeedRolesAsync`, `DistrictSeeder.Seed`) exists but is **commented out**; enable it (run
before `app.Run()`, inside a scope) on first deployment.

## 13. Testing approach (`PotholeApi.Tests/`)

- Test **repositories** against an EF Core **InMemory** `Context` — a `TestHelpers.CreateContext(dbName)` helper
  creates a uniquely named database per test and calls `EnsureCreated()`.
- Logger dependencies satisfied with `NullLogger<T>.Instance`.
- Files: `PotholeRepositoryTests`, `OfficerRepositoryTests`, `RepairTeamRepositoryTests`,
  `Neighbourhood_District_RepositoryTests`.
- Libraries: xUnit, Moq, AutoFixture(+AutoMoq), FluentAssertions; runner configured by `global.json`
  (`Microsoft.Testing.Platform`).
- Caveat: InMemory does not implement spatial SQL, so tests build NTS geometries with a `GeometryFactory(srid 4326)`
  and rely on NTS's in-process `Intersects`.

## 14. Recipe: building a similar project from scratch

1. `dotnet new webapi -n MyApi` (net8.0); add the packages from §11.
2. Create `Models/`, a `Context : IdentityDbContext<ApplicationUser>`, and configure relationships in
   `OnModelCreating` (use `Restrict` deletes where records must not cascade).
3. `dotnet ef migrations add Initial` → `database update`.
4. For each entity: `IRepositories/IXRepository` → `Repositories/XRepository` → DTOs → `Controllers/XController`
   → register in DI (§4).
5. Add Identity + JWT + refresh-token login (§6); seed roles on first run.
6. Add spatial columns/queries if you need maps (§7).
7. Add a gRPC stream + `Channel` + `BackgroundService` if you have bulk/IoT/AI ingestion (§8).
8. Wire Serilog, Swagger, CORS, and the pipeline order (§10).
9. Write repository tests with InMemory (§13).
10. Improvements over this project: apply `[Authorize]` on every controller, move secrets out of
    `appsettings.json`, finish the service layer (controllers depend on services, not repositories/`Context`),
    return DTOs instead of entities, and don't return `ex.Message` to clients in 500 responses.
